# USB-протокол ARDOR GAMING Guardian

[English version](PROTOCOL.en.md) · [← README](../README.md)

Документ описывает, как ARDOR RGB управляет подсветкой клавиатуры. Протокол восстановлен анализом USB-обмена между клавиатурой и фирменным приложением Guardian; всё, что здесь написано, проверено на одной модели — **ARDOR GAMING Guardian 98%, проводное подключение** (радиоканал проверен отдельно, см. [ниже](#беспроводной-режим-24-ггц)). Реализация — [`ardor/device.py`](../ardor/device.py), минимальный самодостаточный пример на 200 строк — [`tools/legacy_ardor.py`](../tools/legacy_ardor.py).

> Неофициальная информация. Проект не связан с ARDOR GAMING / DNS. Используйте на свой риск — см. [отказ от ответственности](../README.md#отказ-от-ответственности).

## Устройство

| | |
|---|---|
| Контроллер | Telink / EVision |
| VID:PID | `0x320F:0x5055` |
| Интерфейс | HID, **usage page `0xFF1C`** (вендорский) |
| Размер отчёта | 64 байта в обе стороны |
| Светодиодов в кадре | 128 слотов (используются 97 + 3 «зеркальных») |

У клавиатуры несколько HID-интерфейсов. Подсветкой управляет только тот, у которого usage page `0xFF1C`, поэтому устройство выбирается так:

```python
devs = [d for d in hid.enumerate(0x320F, 0x5055) if d["usage_page"] == 0xFF1C]
h = hid.device(); h.open_path(devs[0]["path"])
```

## Формат пакета

Каждый запрос — 64 байта. Клавиатура отвечает пакетом той же длины (эхо), и следующий пакет отправляется только после ответа.

| Байт | Значение |
|---|---|
| 0 | `0x04` — всегда |
| 1 | контрольная сумма, младший байт |
| 2 | контрольная сумма, старший байт |
| 3 | команда |
| 4 | размер данных (байт) |
| 5 | смещение, младший байт |
| 6 | смещение, старший байт |
| 7 | `0x00` |
| 8–63 | данные (до 56 = `0x38` байт) |

**Контрольная сумма** — сумма байтов 3…63 по модулю 65536, little-endian:

```python
def packet(cmd, size=0, off=0, data=b""):
    b = [0] * 64
    b[0], b[3], b[4], b[5], b[6] = 0x04, cmd, size, off & 0xFF, off >> 8
    b[8:8 + len(data)] = data
    cs = sum(b[3:]) & 0xFFFF
    b[1], b[2] = cs & 0xFF, cs >> 8
    return b
```

Ответ на чтение несёт данные с того же смещения 8.

## Команды

| Команда | Назначение | Используется в ARDOR RGB |
|---|---|---|
| `0x01` | начало транзакции записи конфигурации | ✅ |
| `0x02` | конец транзакции | ✅ |
| `0x05` | прочитать конфигурацию подсветки (`size=0x22`, `off=0`) | ✅ |
| `0x06` | записать конфигурацию подсветки (`size=0x22`, `off=0`) | ✅ |
| `0x07` | прочитать матрицу клавиш: по 3 байта на светодиод — `0x20`, модификатор, HID usage | ❌ (использовалась при составлении карты) |
| `0x0B` | записать поклавишные цвета режима «custom» (сохраняются в клавиатуре); формат как у кадра `0x12` | ✅ только при выходе в режиме «Снимок эффекта» |
| `0x12` | отправить часть кадра в потоковом режиме (только RAM) | ✅ |
| `0x1A` | запрос состояния, `size=6`; Guardian шлёт его раз в 5 с. В ответе по радио байт 8 = заряд батареи в процентах (`0x64` = 100) | ❌ |

Команды `0x07` и `0x1A` подсмотрены в обмене Guardian и описаны для полноты; ARDOR RGB их не вызывает.

## Конфигурация подсветки (34 байта)

Читается командой `0x05`, пишется транзакцией `0x01` → `0x06` → `0x02`.

| Байт | Значение |
|---|---|
| 1 | **режим** |
| 2 | **аппаратная яркость** 0…4 |
| 5 | флаг «разноцветный» (1 — радуга / случайные цвета, 0 — цвет из байтов 6–8) |
| 6–8 | **цвет режима** R, G, B |
| остальные | скорость, направление и прочее — не разобраны (см. `tools/sniff_steps.py`) |

Номера режимов совпадают со значениями в списке режимов Guardian (`DefaultData/default_light.json`): 1 «Пульсация», 2 «Импульс», 3 «Водопад», 4 «Радуга», 5 «Дыхание», 6 «Статичный», 7 «Интерактивная», 8 «Волна при нажатии», 9 «Стрела», 10 «Мерцание», 11 «Разноцветная мозаика», 12 «Радужный водопад», 13 «Волна», 14 «Геометрический рисунок», 15 «Бегущие капли», 16 «Из стороны в сторону», 17 «Приглушённая разноцветная», 18 «Радужные переливы», 19 «Пользовательская», 20 «Выкл.».

Проверенные на клавиатуре значения:

| Режим | Значение | Пример конфигурации (байты 0–9) |
|---|---|---|
| `0xFE` | **потоковый** — клавиатура показывает кадры, присланные командой `0x12` | — |
| `0x14` | **выключено** | — |
| `0x13` | «пользовательская» — поклавишные цвета из `0x0B` | `00 13 04 00 00 00 31 53 ff 08` |
| `0x06` | статичный цвет | `00 06 04 00 00 00 ff 00 00 08` — красный |
| `0x05` | дыхание | — |
| `0x01` | волна | — |

ARDOR RGB никогда не собирает конфигурацию с нуля: он читает текущую, меняет нужные байты и записывает обратно. Остальные байты копируются как есть.

Пример конфигурации (статичный синий в режиме «custom», снят с Guardian; используется как запасной вариант для восстановления):

```
00 13 04 00 00 00 31 53 ff 08 00 00 00 00 00 00 00 00 02 00 01 00 00 00 00 00 00 00 00 00 00 00 00 00
```

## Потоковый режим

```text
read_config()                      → сохранить исходную конфигурацию
cfg[1] = 0xFE, cfg[2] = 4          → потоковый режим, максимальная аппаратная яркость
write_config(cfg)
loop:
    send_frame(384 байта)          → 7 пакетов 0x12
write_config(исходная)             → при выходе
```

**Кадр** — 384 байта: 128 слотов × RGB, по одному байту на канал, в порядке индексов светодиодов (см. карту ниже). Кадр нарезается на куски по 56 байт: команда `0x12`, `size` = длина куска, `offset` = смещение куска в кадре.

| Пакет | offset | size |
|---|---|---|
| 1 | 0 | 56 |
| 2 | 56 | 56 |
| … | … | … |
| 7 | 336 | 48 |

**Кадры нужно слать непрерывно.** Если поток прекращается, клавиатура через некоторое время сама возвращается к режиму, сохранённому в её памяти. ARDOR RGB шлёт 60 кадров в секунду; утилита `probe.py` — 30. Точный таймаут не измерялся.

Яркость в потоковом режиме выставляется аппаратно на максимум (4), а плавная регулировка делается программно — умножением цветов кадра.

### Восстановление исходного режима

- При старте исходная конфигурация читается и **сохраняется в `%APPDATA%\ardor-rgb\hw_config.bin`**.
- Если при старте клавиатура уже в режиме `0xFE` или `0x14` (то есть её оставила в этом состоянии сама программа — например, после аварийного завершения), то за исходную берётся конфигурация из `hw_config.bin`, а если файла нет — запасная (статичный синий).
- Перед сном ПК клавиатура переводится в режим `0x14` (выключено), чтобы не светиться без потока, а после пробуждения снова в `0xFE`. Исходная конфигурация при этом хранится в памяти программы.

### Режим «когда программа закрыта»

Вместо возврата исходного режима при выходе можно оставить клавиатуру в выбранном аппаратном режиме: выключено (`0x14`), статичный цвет (`0x06`), дыхание (`0x05`), радужная волна (`0x01`, флаг «разноцветный») или **снимок эффекта** — последний кадр записывается командой `0x0B` в поклавишные цвета, и включается режим `0x13`. Это единственный случай, когда программа пишет цвета в постоянную память клавиатуры, и происходит он один раз при выходе.

Записанная так конфигурация сохраняется в `%APPDATA%\ardor-rgb\exit_config.bin`. При следующем запуске, если клавиатура находится ровно в этой конфигурации, она не считается «исходным режимом» пользователя — исходным остаётся сохранённый в `hw_config.bin`.

### «Зеркальные» слоты

На этой раскладке три клавиши совмещают две функции: **Del/PrtSc**, **Ins/Pause**, **PgUp/Home**. У каждой из них два слота светодиода, и прошивка попеременно берёт цвет то из одного, то из другого. Если слоты получают разные цвета, клавиша мерцает. Поэтому перед отправкой кадра второй слот копируется из первого:

| Второй слот | ← основной | Клавиша |
|---|---|---|
| 78 | 13 | Del / PrtSc |
| 79 | 14 | Ins / Pause |
| 81 | 29 | PgUp / Home |

### Как проверялась карта

Утилита [`tools/probe.py`](../tools/probe.py) зажигает светодиоды по одному белым на тусклом синем фоне и спрашивает, какая клавиша загорелась. Так были проверены спорные индексы (13, 14, 29, 44, 57, 59, 78, 79, 81–84 и 105–127). Координаты клавиш для эффектов (`ardor/layout.py`) сняты с фотографии клавиатуры в единицах «ширины клавиши».

## Беспроводной режим (2.4 ГГц)

По радио клавиатура видна через донгл **`320F:5088`** («Wireless Gaming Keyboard») с тем же вендорским интерфейсом `0xFF1C`. Все команды выше работают через него так же, включая потоковый режим. Замеры:

| | Кабель | Радио |
|---|---|---|
| Ответ на пакет | ~1 мс | ~6–10 мс |
| Полный кадр (7 пакетов) | ~15 мс → до 60 кадров/с | ~70 мс → ~14 кадров/с |
| Обновление 2 из 7 кусков | — | ~30 раз в секунду |
| Потери | нет | нет при отправке строго по одному пакету |

- **Пакеты только по одному.** Если отправить все 7 пакетов кадра подряд и потом читать ответы, донгл теряет большую часть (в тесте дошло 3 из 21).
- Пока клавиатура подключена кабелем, донгл на команды отвечает ошибкой (`ff` в байте 3).
- ARDOR RGB радиоканал **пока не поддерживает** — это в планах (отправка только изменившихся кусков кадра, индикатор заряда).

## Подводные камни

- **Guardian должен быть закрыт.** Он работает с тем же интерфейсом — два приложения будут перебивать друг друга.
- **Приложение работает по кабелю.** По радио протокол работает (см. выше), но программа пока ищет только проводной `320F:5055`.
- **Каждый пакет ждёт эхо.** Отправка без чтения ответа приводит к рассинхронизации; `read` с таймаутом 1 с.
- **Ошибка записи = клавиатура отключена.** `hid.write` возвращает −1, если кабель выдернули; программа закрывает устройство и раз в 2 с пытается подключиться снова.
